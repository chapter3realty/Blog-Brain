# Needs: /buyers/undisclosed-flooding/

Shared-tool changes this page would use. None blocks the page; each has a workaround inside the spec or the batch folder.

1. **tools/checkpoint.sh: a pathspec that does not exist yet empties web.patch.** The checkpoint command for this page names `specs/undisclosed-flooding.js` and `chapter3realty/images/2026-10-d/buyers-undisclosed-flooding`, which the research stage does not create. `git add -N -- <all pathspecs>` then fails as a whole ("pathspec did not match"), nothing is intent-added, and the new data folder is left out of the diff: the first checkpoint wrote a 0-byte web.patch. Workaround used: `git -C <web> add -N -- data/2026-10-d/buyers-undisclosed-flooding` before running the same command (web.patch then 14 MB). Fix: run `git add -N` per pathspec and skip the ones that do not exist, or pass `--ignore-missing` with `--dry-run` first.
2. **tools/area-map.js: no fill layer for a flood zone.** Spec `areas` takes 1 to 30 simple polygons of 3 to 400 points. FEMA's high-risk zone and the Florence flood extent are multipolygons with thousands of parts. The page's map (PLAN V4) needs "fills": a GeoJSON layer drawn as a translucent fill under the labels, simplified to the map's scale, with a legend entry. Workaround: the writer draws the SVG inside the spec from `data/2026-10-d/buyers-undisclosed-flooding/map-*.geojson` (already simplified; `map-sfz-outside-sfha-core.geojson` is 136 KB).
3. **tools/glass.js: the closing offer band turns into the slim top bar when listings are live.** COMPACT_RULES styles every navy band that is `:not(:last-child)` of `<main>` as the light top bar. The website's listing edge (and `tools/preview.mjs`) appends the CCMLS notice (`div.hx-wrap`) inside `<main>` after the closing band, so the closing band is no longer the last child: it gets the light panel and keeps its ivory text, which cannot be read (seen at 390 px in the preview). This hits every glass page with a compact top offer. Fix: match the closing band with `:last-of-type` (the notice is a div), or give the two bands classes in mkpage. Workaround: this spec restores the dark panel for `section[navy]:last-of-type` in its own CSS.
